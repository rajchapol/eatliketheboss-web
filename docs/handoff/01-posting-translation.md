## 2. ลงบทความใหม่ได้ 2 ทาง

### ทาง A · ไฟล์ `posts/<slug>.md` (เหมาะกับ Claude)
1. เขียนบทความในน้ำเสียงบอสด้วย skill `eatliketheboss-writing-style` (Google Doc เป็นต้นฉบับ)
2. ก๊อป `posts/_template.md` → `posts/<slug>.md` แล้วกรอก รูปไว้ที่ `posts/images/<slug>/` รูปทุกรูปต้องมี alt text จริงหลัง `|`
3. ตรวจ: `npm run post -- posts/<slug>.md --dry`
4. **รอบอสอนุมัติก่อนเสมอ** แล้วค่อย commit ไฟล์ + รูป และ push เข้า `main` (หรือเปิด PR ให้บอส merge) → `.github/workflows/post-article.yml` ลงเข้า Sanity ให้เอง (ใช้ secret `SANITY_WRITE_TOKEN` · ห้ามขอหรือเก็บ token เอง)
5. รันซ้ำหรือลองแบบ dry ได้ที่ GitHub → Actions → Post article to Sanity → Run workflow

ช่องใน frontmatter ที่ระบบอ่าน: `language, series, episode, title, slug, tagline, city, restaurant{name, originalName, chef, area, cuisine, awards, sameAs}, cover, gallery, quote, bill, billBand, tag, visit, hashtags, publishedAt, seoTitle, seoDescription` + บทนำ + `## ` แบ่งส่วน + `### ชื่อจาน` ทีละจาน (`image: path | alt` ใต้หัวจาน, ใส่ 🕶️ ที่หัวจานถอดแว่น สูงสุด 2 จาน)

### ทาง B · พิมพ์ใน Studio โดยตรง (บอสใช้เอง)
ดูหัวข้อ 5 "วิธีใช้ Studio"

> ⚠️ **ลงไฟล์ซ้ำ (แก้แล้ว 4 พ.ย. 2026):** ถ้าบทความมีใน Sanity แล้ว สคริปต์จะ **ไม่ลบค่าที่บอสตั้งใน Studio** สำหรับช่องที่ไฟล์เว้นว่าง (เช่น The Boss's Bill, ป้าย Event, ประโยคเด่น, แกลเลอรี, ย่าน/รางวัลของร้าน) และ log จะบอกว่าเก็บช่องไหนไว้
> แต่ **ช่องที่ไฟล์กรอกไว้จะทับค่าใน Studio** (ชื่อบทความ บทนำ รายการจาน SEO ฯลฯ) ถ้าบอสแก้ข้อความใน Studio ไปแล้ว ให้แก้ต่อใน Studio หรือก๊อปข้อความล่าสุดจาก Studio มาใส่ไฟล์ก่อน
> ถ้ามีฉบับร่างค้างใน Studio log จะเตือน เพราะถ้าบอสกด Publish ร่างนั้น จะทับสิ่งที่ลงจากไฟล์
> อยากล้างค่าช่องไหน ให้ล้างใน Studio (เว้นว่างในไฟล์ = เก็บค่าเดิม)

- **The Boss's Bill = ระดับราคาโดยประมาณ** ฿฿ (<3,000 บาท) / ฿฿฿ (3,000–7,999) / ฿฿฿฿ (8,000+) ต่อคน · ห้ามบอกราคาจริงในเนื้อหา และ **ห้ามบอกว่าเป็นมื้อเชิญหรือจ่ายเอง**
  - ช่อง `billBand` = ระดับที่แสดง · ช่อง `bill` = ราคาจริง (ไม่แสดง ใช้คำนวณระดับให้ถ้าไม่ได้เลือก)
  - มื้ออีเวนต์พิเศษ → `tag: Event` · โพสต์ที่รับค่าจ้าง → `tag: AD`
- Boss's Pairing เลิกใช้แล้ว (3 พ.ย. 2026) ห้ามใส่กลับ
- ห้ามระบุชื่อที่ทำงานของบอส · ประวัติ: "Hospitality และ F&B มากว่า 15 ปี" · กรรมการ: "Tatler Best Asia-Pacific panelist & more"
- จานถอดแว่น 🕶️ สูงสุด 2 จานต่อมื้อ · ไม่ต้องพิมพ์ "จานนี้อร่อยจนบอสต้องขอถอดแว่นชิม" ในคำบรรยาย (เว็บใส่ให้เอง)
- **เลข Tasting Notes No. ระบบนับเอง** จากเดือน Visit (Mon-YYYY) มื้อเก่าสุด = No. 001 · ห้ามตั้งเอง
- ไปร้านเดิมซ้ำ: พิมพ์ชื่อร้านเหมือนเดิมทุกตัวอักษร (เมืองเดียวกัน) เว็บจะรวมเป็นร้านเดียวพร้อมรายการทุกครั้งที่ไป · ถ้าร้านเปลี่ยนชื่อ ใช้ `restaurant.sameAs: <slug เดิม>` (Studio: "รีวิวครั้งก่อนของร้านนี้")
- ประโยคเด่นของบอส (`quote`) ไม่บังคับ ถ้าใส่จะขึ้นเป็นคำคมตัวโตหลังบทนำ

## 4. รูป
- **ทุกรูปอาหารแสดงแนวนอน 3:2** (ปก จาน การ์ด รางวัล) · ภาพของบอสส่วนใหญ่ 1225×815 อยู่แล้ว
- รูปปกเป็นรูปแชร์ของบทความด้วย: ระบบสร้างรูปแชร์ 1200×630 ให้เอง (ปก + โลโก้ + ชื่อร้าน + Tasting Notes No.) วางทุกอย่างไว้กลางภาพ เพราะ LINE ครอปเป็นสี่เหลี่ยม · เลือกปกที่ **จุดสนใจอยู่กลางภาพ**
- ตัวอักษรจีน/ญี่ปุ่นจะไม่ขึ้นบนรูปแชร์ (ฟอนต์ไม่มี) แต่บนหน้าเว็บขึ้นปกติ
- `gallery` = รูปบรรยากาศร้าน/เชฟ 1–6 รูป ใส่คำบรรยายได้ แสดงหลังบทนำ ก่อนรายการจาน
- alt text ทุกรูป: บรรยายสิ่งที่เห็นจริง + ชื่อร้าน + เมือง (ดูตัวอย่างใน `posts/meet-the-bund.md`)
- รูปมีระบบกันก๊อป (คลิกขวา/ลาก/กดค้างไม่ได้) และลายน้ำโลโก้ของบอส

## 5. วิธีใช้ Studio (ระบบหลังบ้านใหม่)

### เมนูซ้าย
- **บทความ (ภาษาไทย):** ทั้งหมด / แยกตามซีรีส์ / แยกตามเมือง (แสดงบทความต้นฉบับทุกเรื่อง)
- **คำแปล (EN / 日本語 / 中文):** แยกตามภาษา (ไม่มีปุ่ม + ตรงนี้ คำแปลต้องสร้างจากบทความไทย)
- **งานที่ต้องทำ:** รายการที่หายไปเองเมื่อแก้เสร็จ: ภาษาเพี้ยน · ร่างใหม่ยังไม่เคยเผยแพร่ · แก้ค้างยังไม่กดเผยแพร่ · ยังไม่มีระดับราคา · ยังไม่ใส่ Visit · ไม่มีรูปปก · รูปไม่มี alt · SEO ไม่ครบ/ยาวไม่พอดี · ยังไม่มีคำแปล English
- **เมือง** · **ตั้งค่าเว็บ / ข้อความทุกหน้า**

### แท็บในบทความ (เรียงตามลำดับที่กรอก)
1. **ร้าน & บทนำ** — ซีรีส์ ชื่อบทความ slug คำโปรย เมือง ข้อมูลร้าน (ชื่อ ชื่อเดิม เชฟ ย่าน ประเภท รางวัล รีวิวครั้งก่อน) รูปปก แกลเลอรี บทนำ ประโยคเด่น
2. **รายการจาน** — ชื่อจาน (ชื่อเดิม) คำบรรยาย ติ๊กถอดแว่น รูปจาน
3. **ราคา & วันที่ไป** — The Boss's Bill (฿฿/฿฿฿/฿฿฿฿) · มื้ออีเวนต์? (ไม่ใช่/Event/AD) · ราคาจริง (ไม่แสดง) · Visit · แฮชแท็ก · วันที่เผยแพร่
4. **SEO** — Meta title (≤60) และ Meta description (120–155) **มีตัวนับตัวอักษรบอกว่าขาด/เกินกี่ตัว**
5. **ภาษา / คำแปล** — แผงแสดงทุกภาษาของบทความนี้ + ปุ่มสร้างคำแปล
- **ทุกช่อง** = ดูทุกช่องในหน้าเดียว

### ปุ่มในบทความ (มุมขวาล่าง ข้าง Publish)
- **เปิดดูบนเว็บ** — เปิดหน้าจริง (ต้องเผยแพร่ก่อน รอเว็บอัปเดต 2–3 นาที)
- **ลบบทความ…** — บอกก่อนว่าหน้าเว็บไหนจะหาย ลบทั้งร่าง+ฉบับเผยแพร่ แล้วปิดหน้าให้ · ถ้ามีคำแปลผูกอยู่จะลบไม่ได้จนกว่าจะลบคำแปลก่อน

### ทำคำแปลใน Studio
1. เปิดบทความไทย (ต้องเผยแพร่แล้ว) → แท็บ **5 ภาษา / คำแปล**
2. กด **+ English / 日本語 / 中文** → ระบบสร้างร่าง id `<id ไทย>-<lang>` ผูกกับบทความไทยให้ คัดลอกร้าน รูป จาน ราคา Visit slug และข้อความไทยไปให้แปลทับ (ยกเว้น SEO ต้องเขียนใหม่)
3. ถ้าภาษานั้นมีอยู่แล้ว ปุ่มจะเปิดอันเดิม
- ช่อง "บทความนี้เป็นภาษา" **ล็อกไว้ แก้เองไม่ได้** (เคยมีปัญหาบอสเปลี่ยนบทความไทยเป็น English เอง) · ถ้าเจอบทความไทยที่ภาษาเพี้ยน จะมีปุ่ม **"เปลี่ยนกลับเป็นบทความภาษาไทย"** ในแท็บ 5

### ทำคำแปลด้วยไฟล์ (วิธีที่ใช้กับ 6 ร้านเซี่ยงไฮ้)
- ไฟล์ `posts/<slug>.<lang>.md` slug เดียวกับต้นฉบับ · `language: en`
- คงชื่อร้าน ชื่อจาน ชื่อเชฟตามต้นฉบับ (หัว `###` ห้ามแปลถ้าเป็นชื่อเดิม) · น้ำเสียงนักวิจารณ์ของบอส · alt รูปแปลด้วย
- ร่างไว้ที่ `drafts/translations/` ก่อน (โฟลเดอร์นี้ไม่ถูกเผยแพร่) → บอสอนุมัติ → ย้ายไป `posts/` → merge เข้า main
- ไฟล์จะใช้ id `article-<slug>-<lang>` เดียวกับปุ่มใน Studio → ถ้ามีร่างใน Studio อยู่แล้ว ให้ลบร่างนั้นก่อน
- ตัวอย่างน้ำเสียงที่บอสอนุมัติแล้ว: `posts/meet-the-bund.en.md` (คำที่บอสแก้: หอยปีกนก = torigai, ใบชะพลู = betel leaves, ลิลลี่บับ = lily buds)

### บนเว็บ
- ปุ่ม **"อ่านภาษา: ไทย · English"** อยู่ใต้ breadcrumb ของบทความ ขึ้นเฉพาะบทความที่มีคำแปลจริง
- **ไม่มีระบบแปลอัตโนมัติ** (ลอง Google Translate 2 รอบแล้วพัง บอสสั่งปิดถาวร) ห้ามเพิ่มกลับ
- หน้ารวม (หน้าแรก ค้นหา เมือง) ยังเป็นภาษาไทย แปลเฉพาะหน้าบทความ

## 6. งานค้าง / ข้อเสนอแนะ
1. **แปลบทความใหม่ทุกเรื่องเป็นอังกฤษ** ตามรูปแบบเดิม (ร่างใน `drafts/translations/` → บอสอนุมัติ)
2. ญี่ปุ่น / จีน: ยังไม่มี · ถ้าจะเริ่ม แนะนำร้านในญี่ปุ่นเป็นภาษาญี่ปุ่นก่อน
3. ตั้งระดับราคา (billBand) ให้ทุกบทความ ดูรายการ "งานที่ต้องทำ → ยังไม่มีระดับราคา"
4. ใส่ "ประโยคเด่นของบอส" ในบทความเด่นๆ ช่วยให้บทความยาวมีจังหวะ
5. ถ้าบอสเปิด LINE OA ในอนาคต ใช้ RSS `https://eatlikeboss.com/rss.xml` ส่งแจ้งเตือนบทความใหม่อัตโนมัติได้
6. ในอนาคตอาจเพิ่มสคริปต์ "ดึงบทความจาก Sanity กลับมาเป็นไฟล์" ให้ไฟล์กับ Studio ตรงกันเสมอ (ข้อความที่ไฟล์กรอกไว้ยังทับ Studio ได้ ดูหัวข้อ 2)
