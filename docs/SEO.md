# SEO — Eat Like The Boss website

แนวทาง SEO สำหรับตอนสร้างเว็บจริง และสิ่งที่ต้องกรอกทุกครั้งที่โพสต์
เป้าหมาย: คนที่ค้น "ร้าน [ชื่อร้าน] รีวิว", "fine dining โตเกียว", "omakase กรุงเทพ" เจอบทความของบอส ทั้งใน Google และใน AI search

## 1. โครง URL (ตั้งครั้งเดียว ห้ามเปลี่ยนภายหลัง)

| หน้า | URL |
| --- | --- |
| บทความรีวิว | `/review/[city]/[restaurant-slug]/` เช่น `/review/tokyo/sezanne/` |
| มื้ออาหารเปลี่ยนโลก | `/history/ep-14-yalta-1945/` |
| บอสพาดื่ม | `/drinks/[slug]/` |
| เมือง | `/city/tokyo/` |
| ค้นหาร้าน | `/restaurants/` (ตัวกรองใช้ `?city=tokyo&cuisine=japanese` + ใส่ canonical ไปหน้าหลัก) |
| Glasses Off Awards | `/glasses-off-awards/2026/` |
| เกี่ยวกับบอส | `/about/` |
| ภาษาอื่น | ใส่หน้า: `/en/review/tokyo/sezanne/`, `/ja/…`, `/zh/…` |

- slug เป็นภาษาอังกฤษตัวเล็ก คั่นด้วย `-` ใช้ชื่อร้านตามภาษาโรมัน ไม่ใส่ภาษาไทยใน URL
- ถ้าต้องเปลี่ยน URL ใส่ redirect 301 ทุกครั้ง

## 2. ช่องที่ต้องกรอกทุกบทความ (ใส่เป็นช่องในระบบหลังบ้าน)

| ช่อง | กติกา |
| --- | --- |
| Meta title | ≤ 60 ตัวอักษร: `[ร้าน] [เมือง] รีวิว Fine Dining — บอสพาชิม` |
| Meta description | 120–155 ตัวอักษร เขียนแบบบอส บอกจุดเด่นของมื้อ + เมือง + ประเภทอาหาร ห้ามใส่ดาวหรือคะแนน |
| Slug | ตามข้อ 1 |
| ภาพแชร์ (OG image) | 1200×630 จากภาพปกบทความ ใช้ overlay แบรนด์ |
| Alt ของทุกภาพ | บรรยายจานจริง เช่น "ซูชิโอโทโระบนข้าวอุ่น ร้าน [ร้าน] โตเกียว" ไม่ใช่ "IMG_2031" |
| ชื่อไฟล์ภาพ | `sezanne-tokyo-otoro.avif` |
| วันที่เผยแพร่ / อัปเดต | แสดงบนหน้า และใส่ใน structured data |
| ร้านในฐานข้อมูล | ผูกบทความกับร้าน (ชื่อ เมือง ย่าน ประเภท เชฟ) เพื่อสร้างหน้ารวมและลิงก์ภายในอัตโนมัติ |

## 3. Structured data (JSON-LD ที่ระบบสร้างให้อัตโนมัติ)

- **บทความรีวิว:** `Review` ที่มี `itemReviewed` เป็น `Restaurant` (ชื่อ ที่อยู่ เมือง ประเภทอาหาร ช่วงราคา) และ `author` เป็น `Person` (บอส ลิงก์ไป `/about/`)
  - **ไม่ใส่ `reviewRating`** เพราะแบรนด์ไม่ให้ดาวหรือคะแนน ผลคือจะไม่มีดาวขึ้นใน Google ซึ่งตรงกับแบรนด์ และไม่เสี่ยงโดนลงโทษเรื่อง rating ที่ไม่มีจริง
- **ทุกบทความ:** `Article` (headline, image, datePublished, dateModified, author)
- **ทุกหน้า:** `BreadcrumbList` ตาม breadcrumb ที่แสดงบนหน้า
- **หน้าแรก:** `WebSite` + `Organization` (โลโก้ ลิงก์ Facebook / Instagram ใน `sameAs`)
- **หน้าเกี่ยวกับบอส:** `Person` (ชื่อเพจ, งาน Hospitality และ F&B 15+ ปี, Tatler Best Asia-Pacific panelist) ห้ามใส่ชื่อบริษัทที่บอสทำงาน
- **Glasses Off Awards:** `ItemList` ของจานที่ได้รางวัล

## 4. หลายภาษา (hreflang)

- ทุกหน้ามี `<link rel="alternate" hreflang="th|en|ja|zh-Hans">` ครบทุกภาษา + `x-default` ไปหน้าไทย
- แต่ละภาษามี meta title / description ของตัวเอง (แปลพร้อมเนื้อหา)
- `<html lang>` ตรงกับภาษาหน้า ชื่อร้าน ชื่อจาน ชื่อเชฟ ไม่แปล

## 5. ลิงก์ภายใน (ช่วยทั้ง SEO และคนอ่าน)

- บทความ → หน้าเมือง, หน้าร้านอื่นในเมืองเดียวกัน (More Tasting Notes), Glasses Off Awards ถ้ามีจานถอดแว่น
- หน้าเมือง → ทุกบทความในเมือง จัดตามประเภทอาหาร
- Footer ทุกหน้า → เมืองหลัก ซีรีส์ทั้ง 3 Awards และเกี่ยวกับบอส
- breadcrumb ทุกหน้า: หน้าแรก / [ซีรีส์] / [เมือง] / [ร้าน]

## 6. ความเร็ว (Core Web Vitals)

- ภาพเป็น AVIF/WebP หลายขนาด (`srcset`) ภาพแรกของหน้าโหลดทันที ที่เหลือ `loading="lazy"`
- ทุกภาพกำหนดสัดส่วนไว้ (ใช้ aspect-ratio แล้วในดีไซน์) หน้าไม่กระตุกตอนโหลด
- ฟอนต์: ตัด subset เฉพาะไทย+ละติน, `font-display: swap`, preload เฉพาะฟอนต์หัวข้อ
- เว็บ static (Astro) โหลดแทบไม่มี JavaScript ยกเว้นหน้าค้นหาร้านและแตะดูรูปใหญ่
- เอฟเฟกต์ทั้งหมดเป็น CSS และปิดเองเมื่อผู้ใช้ตั้งค่าลดการเคลื่อนไหว

## 7. ไฟล์ระบบ

- `sitemap.xml` อัตโนมัติ (แยกตามภาษา) + ส่งใน Google Search Console
- `robots.txt` เปิดให้ index ทุกหน้า ยกเว้นหน้าผลค้นหาที่มีตัวกรองซ้อนหลายชั้น
- canonical ทุกหน้า
- RSS feed ของบทความ

## 8. ความน่าเชื่อถือ (E-E-A-T) — จุดแข็งของบอส

- ทุกบทความแสดง "โดย บอส" ลิงก์ไปหน้าเกี่ยวกับบอส + วันที่เผยแพร่ + Visit
- The Boss's Bill และป้าย AD / Event บอกที่มาของมื้อชัดเจน
- ภาพจริงจากมื้อจริงทุกภาพ ไม่ใช้ภาพจากร้านหรือภาพสต็อก
- หน้าเกี่ยวกับบอสมีประสบการณ์ 15+ ปี และ Tatler Best Asia-Pacific panelist & more

## 9. โซเชียลกับเว็บ

- โพสต์ Facebook / Instagram ยังห้ามใส่ลิงก์ตามกฎแบรนด์ ให้คนมาที่เว็บผ่านลิงก์ใน bio และปุ่มบนเพจ
- เว็บเป็นที่เดียวที่บทความเต็มมีลิงก์ภายในและ structured data ครบ จึงเป็นตัวที่ Google เก็บ
